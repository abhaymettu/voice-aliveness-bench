The finding

The gap tracks how long the answer is, not how hard the question was

gap vs question difficulty gap vs reply length gap vs difficulty, reply length partialled out

A person takes longer to answer “what is the meaning of life” than “what is two plus two”. None of these agents do. The gap tracking reply length is an accident of synthesising the whole utterance before speaking. Nothing in any of these systems models difficulty at all.

How it was run

One definition of the gap, and no blocking

One definition, used by every scorer, imported rather than reimplemented from harness/audio.py in the sibling aliveness-threshold repo so the two cannot drift. Any deviation would make cross-system numbers meaningless.

Systems are interleaved turn by turn, never run in blocks

The sibling repo re-ran its own unchanged code twenty minutes apart the same evening and measured 1452 ms, then 807 ms — a 1.8× swing that loadavg did not explain. On this machine, blocking by system would confound the system with the wall clock by more than most effects worth reporting.
